# مدل هویت و Principalها — S05-W01

هفت‌سو هویت انسان و سرویس را از ابتدا جدا نگه می‌دارد. هر درخواست با یک `Principal` شامل شناسهٔ غیرقابل حدس، نوع، مستأجر، نقش‌ها و Scope ارزیابی می‌شود.

| نوع | شناسه | کاربرد |
|---|---|---|
| `anonymous` | Request ID | مرور عمومی بدون نشست |
| `user` | User ID | کاربر حقیقی بازارگاه |
| `business` | Business ID | مالک یا عضو کسب‌وکار |
| `workforce` | Employee ID | مدیر، پشتیبان، ناظر و اپراتور مالی |
| `service` | Service name | ارتباط داخلی Web، API و Chat |

قواعد پایه:

- تمام داده‌ها در Tenant قرار می‌گیرند و Tenant پیش‌فرض `public` است.
- شماره تلفن و ایمیل شناسه عمومی نیستند؛ نرمال، رمزگذاری و تنها با مجوز مناسب نمایش داده می‌شوند.
- Impersonation به‌طور پیش‌فرض ممنوع است و در آینده فقط با Step-up، دلیل و Audit صریح فعال می‌شود.
- ورود OTP کاربر در `S18` پیاده‌سازی می‌شود؛ این استیج قرارداد هویت و کنترل‌های زیرساختی آن را تثبیت می‌کند.

قرارداد اجرایی در `security/identity-model.json` و Typeهای مشترک در `packages/contracts` قرار دارد.
