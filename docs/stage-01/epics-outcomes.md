# Epicها و Outcomeهای برنامه

| Epic | Outcome قابل سنجش |
|---|---|
| E01 حاکمیت و معماری | هر تغییر مهم قابل ردیابی به ADR، Work و SHA باشد. |
| E02 Taxonomy و Forms | فیلد و فیلتر هر دسته بدون Release کد قابل نسخه‌بندی باشد. |
| E03 Geo | شهر/محله/Polygon با Query مکانی معتبر و قابل مشاهده باشد. |
| E04 Discovery | کاربر با متن، فیلتر و نقشه به نتیجه مرتبط برسد. |
| E05 Listing | ثبت، بررسی، انتشار، ویرایش و انقضا بدون گم‌شدن تاریخچه انجام شود. |
| E06 Identity | OTP و Session امن، قابل ابطال و قابل ممیزی باشد. |
| E07 Chat | پیام مرتب، idempotent، قابل بازیابی و ایمن باشد. |
| E08 Moderation/AI | تصمیم قابل توضیح، Reason Code و Human Override داشته باشد. |
| E09 Fraud/Duplicate | آگهی تکراری ۲۴ساعته پیش از انتشار متوقف یا صف‌بندی شود. |
| E10 Admin/RBAC | هر کارمند فقط داده و Action مجاز خود را ببیند. |
| E11 CRM | Case، SLA، Timeline و Escalation یکپارچه باشد. |
| E12 Payments/Ledger | هر حرکت پولی دوبل، idempotent و قابل تطبیق باشد. |
| E13 BNPL | Provider قابل تعویض و Schedule/Settlement قابل ممیزی باشد. |
| E14 Monetization | ارتقای آگهی و اشتراک با Entitlement روشن اعمال شود. |
| E15 Notifications | پیام وضعیت‌محور با Template نسخه‌دار و Delivery Log ارسال شود. |
| E16 Analytics/SRE | KPI، SLO، Alert و Incident روی داده معتبر عمل کند. |
